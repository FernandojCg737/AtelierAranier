**Base de Datos : Calificacion** (tabla `calificacion`, modelo [`Calificacion`](/backend/app/models/p4_ventas.py))
- `venta_id` es `UNIQUE` -- una sola calificacion por venta (asegura la unicidad que valida el mensaje 3 en el nivel de aplicacion, ademas del constraint de la BD)
- Insercion directa via ORM (mensaje 4)
- Agregaciones `AVG`/`COUNT`/`GROUP BY` (mensajes 7-8), con `JOIN` a `venta`, `sucursal`, `cliente`, `usuario` y (via `LEFT JOIN`) `venta_presencial`/`usuario` para el empleado que atendio la venta

## Notas

- El mensaje 4 (`sp_RegistrarCalificacion`) sugiere un stored procedure, pero es una **insercion ORM directa** (`db.add(Calificacion(...))`, `db.commit()`) -- no existe ningun `sp_registrar_calificacion` en las migraciones. Mismo patron ya visto en CU10 (reservas) y CU18 (recomendaciones): el diagrama nombra el mensaje como si fuera un SP aunque el codigo real sea SQL crudo u ORM puro.
- El mensaje 2 (`VerificarPropiedadYPagoCompletado`) esta dibujado hacia "BD : Calificacion", pero en realidad consulta las tablas `venta` y `pago` -- confirma dos cosas a la vez: que la venta le pertenece al cliente que esta calificando (`Venta.cliente_id == cliente.id`, linea [46](/backend/app/api/v1/endpoints/calificaciones.py#L46)) y que su pago esta `completado` (linea [49](/backend/app/api/v1/endpoints/calificaciones.py#L49)) -- no se puede calificar una compra ajena ni una todavia no pagada/pendiente de verificacion QR.
- El resumen del mensaje 7 (`CalcularPromedioYDistribucion`) es **siempre global**: el filtro `estrellas` del mensaje 6.1 solo acota la tabla de detalle (mensaje 8), no el promedio/distribucion que se muestra arriba del panel -- asi el admin siempre ve la reputacion real completa, aunque este mirando solo las calificaciones de 1 estrella en la tabla.
- El detalle de cada calificacion (mensaje 8) incluye, via `LEFT JOIN venta_presencial` + `usuario`, el **nombre del empleado que atendio la venta** cuando fue una venta presencial -- pensado para poder cruzar una mala calificacion con quien atendio esa venta puntual (segun el comentario del codigo). Para ventas digitales (PayPal/QR) ese campo queda `null`, ya que no hay un empleado asociado.
- No existe ningun mensaje ni endpoint que permita **editar o eliminar** una calificacion, ni por el cliente ni por el staff -- una vez registrada (protegida por el `UNIQUE` en `venta_id` y la verificacion del mensaje 3), queda fija.
