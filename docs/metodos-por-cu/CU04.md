## Notas

- El diagrama muestra `BuscarSucursal()` y `ObtenerSucursalCreada()/ObtenerSucursalActualizada()` como mensajes separados, pero en el codigo real es la **misma funcion** [`_get_sucursal_or_404()`](/backend/app/api/v1/endpoints/sucursales.py#L41) reutilizada en los tres flujos (alta, edicion, baja) para: (a) validar que la sucursal existe antes de operar, y (b) re-obtenerla ya actualizada para devolverla al frontend.
- La eliminacion esta protegida con un `try/except DBAPIError` (linea [138](/backend/app/api/v1/endpoints/sucursales.py#L138)): si la sucursal tiene inventario, ventas o reservas asociadas, la base de datos rechaza el `DELETE` por integridad referencial y el backend lo traduce a un `409 Conflict` -- este camino de error no aparece en el diagrama.
- `sp_crear_sucursal` y `sp_actualizar_sucursal` reciben tambien `latitud`/`longitud` (agregados esta sesion para CU01, validacion de asistencia por ubicacion) -- el diagrama original no los contempla porque son un agregado posterior al diseño original de este CU.
